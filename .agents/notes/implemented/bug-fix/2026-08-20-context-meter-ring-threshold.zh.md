# Agent Note: 上下文仪表圆环跟随压缩阈值

Status: implemented

[English](2026-08-20-context-meter-ring-threshold.md) | 中文

## 问题

[ContextMeter 决定](../feature/2026-08-05-composer-context-meter-breakdown.md)提供了可配置的自动压缩阈值，但圆环始终相对于模型完整上下文窗口归一化占用率。改变阈值只改变了压缩策略和滑块文案，没有改变圆环完成一整圈的位置，因此指标没有反映所选限制。

## 决定

圆环描边把绝对的投影占用率相对于所选阈值归一化，并把结果限制在 100%。本地化的占用率标题、`~已用 / 容量` 数字和组成进度条仍相对于完整上下文窗口归一化，因此继续报告实际容量使用情况。阈值是浏览器与 preset-local 压缩后端共享的 Host `compaction-policy` setting；`compaction-basic` 在 `agent/pre-step` 中读取它，此时当前步骤已经结束而下一次模型请求尚未组装。浏览器保留 Host 值的实时本地显示，并对旧的仅本地 setting 执行一次迁移。

圆环使用未四舍五入的归一化值以保持 SVG 进度平滑。显示的占用率仍是既有投影整数值；达到或超过所选阈值时圆环显示完整，而不会绘制超过一整圈的描边。

## 备选方案

**把标题和组成进度条也按所选阈值缩放。** 否决，因为这会让面板把相对于阈值的百分比伪装成模型的实际上下文占用率，并让数字与进度条总长不一致。

**让圆环继续相对于完整上下文窗口归一化。** 否决，因为配置的阈值会影响压缩时机，却不会影响视觉上的限制指标，这正是本次修复要解决的问题。

**在圆环上再绘制一个阈值标记。** 否决，因为现有 14px 控件没有空间容纳清晰的独立标记；让阈值成为圆环的完成点，可以直接读出所选限制。

## 影响

阈值为 25% 时，占用率达到模型窗口的 25% 即填满圆环；面板仍显示绝对占用率与容量数字。降低阈值会立即让圆环反映所选限制；下一次 `agent/pre-step` 边界会在另一个模型请求前执行自动压缩，随后当前轮次继续。显式的 `立即压缩` 操作仍仅限 idle 状态。

`packages/client/ui-conversation/tests/context-meter.client.spec.tsx` 验证改变阈值会改变 SVG 描边比例并保留持久化设置。组件仍由现有 ContextMeter 组装 GUI 测试路径覆盖。
