# Agent Note: Web 外壳抑制浏览器原生上下文菜单

Status: implemented

[English](2026-08-19-web-shell-native-context-menu-suppression.md) | 中文

## 问题

浏览器上下文菜单会覆盖 Harness 控件，并暴露不操作 Harness 状态的浏览器动作。应用内右键还可能用浏览器拥有的第二个菜单中断产品内指针交互。

## 决策

根应用框架 `AppFrame` 会阻止 Harness UI 内 `contextmenu` 事件的默认动作。事件仍按 React 传播，因此组件可以实现明确的产品上下文菜单，同时继续抑制浏览器菜单。

文本选择仍然可用。若控件的 click 可能在拖动选择结束时产生，则文档选择未折叠时忽略该 click；模型选择器采用此规则，并将触发器标记为不可选择。

## 备选方案

**在 `document` 上抑制菜单。** document 全局监听器还会拥有已挂载应用以外的内容，并需要显式生命周期清理。根 frame 让该策略与产品 UI 具有相同生命周期和范围。

**仅在各个组件上禁用右键。** transcript、composer、sidebar 与 overlay 的浏览器 chrome 会继续不一致，而且每个新组件都必须记住该策略。

**打开控件前清除文本选择。** 这会破坏已完成的选择，并仍把选择手势解释为命令。忽略由此产生的 click 可保留用户选择，并要求之后明确激活控件。

## 后果

在 Harness 内右键不再打开浏览器 chrome。该菜单中的原生复制和搜索动作在此不可用；键盘复制与 Harness 自有动作仍可用。产品自有上下文菜单可以选择接入，而不会与浏览器菜单竞争。组件测试固定根级取消与模型触发器的选择安全行为。
