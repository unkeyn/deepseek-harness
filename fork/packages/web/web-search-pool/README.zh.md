# @deepseek-ai/dsh-fork-web-search-pool

用于 `ctx.web` 的用户管理通用 HTTP 搜索提供方。它把端点和响应映射保存在 `web-search-pool` 设置命名空间中，并且只通过凭据引用保存 API 值。浏览器设置卡可以为每个提供方添加多个提供方和多把只写密钥。

## 配置

每个提供方可以配置 HTTPS 端点、提供方优先级、GET 或 POST 查询位置、认证模式，以及结果数组和来源字段的点路径。每把密钥都有自己的优先级和最大并发请求数。默认路由将 `custom-pool` 放在官方 DeepSeek 搜索提供方之前；当 pool 为空或耗尽时，会回退到下一个配置的 Web 提供方。

`maxAttempts` 限制一次搜索中的密钥轮换次数。失败密钥会进入冷却并记录不含凭据值的脱敏错误摘要。HTTP 401/403 还会在冷却期间隔离该密钥；429、服务器、解析和传输失败仍属于可重试的冷却状态。成功会清除健康元数据。取消不会轮换到另一把密钥。

设置文档只包含引用和脱敏健康元数据。密钥值通过 `credentials.set` 写入，并在请求前立即解析。浏览器只收到已配置状态和错误元数据，从不收到密钥字面值。

## 模型体验

现有的 `web_search` 工具会收到自定义提供方输出的标准化 URL、标题、摘要和发布日期字段。`web_search_pool_status` 提供提供方／密钥标识符、优先级、可用性、冷却／隔离时间、并发限制和脱敏错误，不返回密钥值。`web_search_pool_rotate` 可以按名称启用、禁用或冷却密钥，并且不接受凭据值。提供方和密钥失败仍是结构化 `WebError` 诊断；耗尽的自定义 pool 可以回退到配置的下一个 Web 提供方。

#### KV Cache effect

pool 设置和健康元数据不会写入对话上下文或 KV cache。pool 挂载后，两个管理工具会把 schema 和提示指导加入模型请求；它们的结果作为普通工具结果记录，并且只包含脱敏元数据。

## Known Limitations and Deferred Work

- 适配器接受 JSON 结果体并映射一个配置的结果数组；不支持提供方专用请求体、分页和生成式答案文本。
- 冷却和错误元数据与用户编辑共用设置文档。设置服务会拒绝并发的过期编辑，健康持久化失败不会改变搜索结果。
- 密钥选择是每次请求按优先级排序的有界故障转移，不是加权 round-robin，也不支持提供方专用请求体或分页。
