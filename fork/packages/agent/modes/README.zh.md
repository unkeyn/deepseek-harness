# @deepseek-ai/dsh-fork-agent-modes

Пер-сессионный ростреж специализированных режимов, между которыми модель маршрутизируется сама: модель вызывает `select_mode` в начале подходящей задачи, инструменты `subagent_<mode>` делегируют работу подтипам режимов, а пользователь назначает каждому режиму модель и кастомную инструкцию из меню композера — с сохранением в settings-namespace `agent-mode-assignments`, без правки конфигов. Состояние — durable-события сессии: resume, fork и replay восстанавливают его из лога.

## Ростреж

- `default` — общая работа; вызов не нужен.
- `scout` — быстрое read-only исследование кодовой базы («где что есть»).
- `revisor` — внимательное рассмотрение: найти, собрать, проверить информацию.
- `design` — работа над пользовательским дизайном.
- `agents` — работа, скоординированная между несколькими субагентами.
- Легаси-id `smol`/`big`/`code` остаются валидными в старых логах и команде `/mode`, но поверхностью маршрутизации не показываются.
- `angel` — переключатель, а не режим (см. ниже).

## Как работает маршрутизация

Постоянная секция `agent-mode:routing` (order 45) объясняет модели, когда какой режим уместен, и просит вызывать `select_mode` один раз в начале подходящей задачи. Инструмент дописывает `agent-mode/selected`, назначенная режиму модель — через `ctx.llm.resolveCallConfig` и реестр выбора шлюза (`@deepseek-ai/dsh-fork-agent-model-selection`) — вступает в силу со следующего шага вместе с секцией инструкции режима (`agent-mode:instruction`, order 50). Возврат к `default` снимает переопределение модели.

## Субагенты режимов

`subagent_default`, `subagent_agents`, `subagent_design`, `subagent_revisor` и `subagent_scout` запускают ребёнка на сконфигурированном провайдере `ctx.subagents` (по умолчанию `spawn`) с инструкцией режима в начале промпта задачи и назначенной моделью режима в `agentOptions`. Одноразовые foreground-запуски; ненормативная причина остановки превращается в ошибку инструмента с диагностикой провайдера.

## Назначения пользователя

Settings-namespace `agent-mode-assignments` хранит `{ models: { <режим>: { provider, model, reasoningEffort? } }, instructions: { <режим>: текст }, presets: { <имя>: { models, instructions } } }`. Меню композера пишет через settings-RPC; контроллер читает живьём. Неназначенный режим использует собственную модель сессии и встроенную инструкцию; `roles.*.instruction` в конфиге плагина остаётся статическим фолбэком. Пресет — именованный снимок полной конфигурации моделей и инструкций; применение заменяет карты models и instructions целиком, сохраняя все записанные пресеты.

## Durable-состояние и команды

`agent-mode/selected` (`{ mode }`) и `agent-mode/angel` (`{ enabled }`) — log-only, замена целого значения; `foldSelected`/`foldAngel` их складывают. `/mode <name>` и `/angel [on|off]` остаются ручным переопределением. Проекция `agentMode` складывает `{ selected, angel }` для UI.

## Конфигурация

```yaml
- id: agent-modes
  name: '@deepseek-ai/dsh-fork-agent-modes'
  config: {}
  # Опциональный компаньон angel:
  # config:
  #   angel: { provider: deepseek-official, model: deepseek-chat, maxTokens: 512 }
```

`angel.provider`/`angel.model` обязательны при наличии секции; `angel.instruction` заменяет встроенный промпт компаньона; `delegationProvider` задаёт провайдера `ctx.subagents` (по умолчанию `spawn`). Неизвестные ключи падают при загрузке (Schemastery).

## Model Experience

### Секции маршрутизации и инструкции

- **Что видит модель** — руководство по маршрутизации (~90 токенов) в каждом запросе; инструкция активного режима на order 50, когда непуста.
- **Эффект по токенам** — руководство маршрутизации — фиксированная цена запроса; инструкция добавляет свою длину, пока активна.
- **Эффект KV-кэша** — руководство стабильно (дружелюбно префиксу); смена режима переписывает промпт с order 50 и далее.

### Делегация субагентам режимов

- **Что видит модель** — финальный текст ребёнка как `{ result }`; неудачи несут причину остановки и диагностику.
- **Эффект по токенам** — беседа ребёнка отдельна; родитель платит только результат инструмента.
- **Эффект KV-кэша** — обычный результат инструмента в истории родителя.

### Внедрение angel

- **Что видит модель** — одно plugin-сообщение («Angel companion notes…»), попадающее в следующий принятый запрос после триггерного.
- **Эффект по токенам** — длина ответа один раз плюс сам вызов компаньона (в основном транскрипте его нет).
- **Эффект KV-кэша** — append-рост после переиспользуемого префикса.

## Known Limitations and Deferred Work

- Назначенная режиму модель применяется с шага после `select_mode`, поэтому первый запрос свежего маршрутизированного задачи идёт на предыдущей модели.
- Инструменты делегации — foreground one-shot; фоновые и continuable-запуски остаются за основным инструментом `subagent`.
- Модель компаньона angel берётся из конфига, а не из UI назначений.
- Назначенная модель валидируется в момент выбора, так что устаревшая пара провайдер/модель роняет именно выбор с именованной ошибкой, а не назначение.
