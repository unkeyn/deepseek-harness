# @deepseek-ai/dsh-fork-agent-model-selection

Кросс-плагинный реестр пер-агентных ссылок выбора модели, которые устанавливает веб-API-шлюз. Шлюз сохраняет владение ссылкой и её трёхуровневый приоритет чтения (выбор в процессе → записанный request header → дефолт развёртывания); сервис лишь публикует установленную ссылку как `ctx.agentModelSelections`, чтобы другие плагины применяли выбор через ТУ ЖЕ объектную ссылку, которую читает шлюз, — один писец на агента, последняя запись выигрывает, как и ручной выбор в сиде модели.

## Сервис

`AgentModelSelections` (`ctx.agentModelSelections`, без конфигурации):

- `bind(agent, ref)` — шлюз публикует ссылку, установленную для агента (вызывается из ленивого `selectionFor` шлюза).
- `for(agent)` — опубликованная ссылка либо `undefined`, пока шлюз её не установил (headless- и не-веб-композиции её не устанавливают).

Пишущие резолвят цель сами (`ctx.llm.resolveCallConfig`) и присваивают `ref.current`; очистка — присваивание `undefined`, что возвращает ссылке её уровни «из лога/дефолт».

## Model Experience

Сам по себе модель не видит. Выбор, записанный через опубликованную ссылку, вступает в силу со следующего шага, входящего в сборку промпта, — идентично вызову `selectModel` шлюза.

## Known Limitations and Deferred Work

- Реестр наполняет только fork API-шлюз; композиция без него не даёт доступной для записи поверхности выбора, и пишущие обязаны трактовать `for(agent) === undefined` как «слоты моделей не поддерживаются».
