# Agent Note：上下文计量的悬停交换、限制滑杆与合并的 Host 写入

Status: implemented

[English](2026-08-24-header-context-meter.md) | 中文

## 问题

fork 的上下文计量器用一个 `<select>`（在阈值滑杆旁）回答按会话限制——两个不同的变量（绝对 token 上限；百分比触发点）被呈现成两个互相竞争的控件——而组成明细行（系统提示词、工具、对话消息）被埋在面板里一次点击深，面板在显式关闭前一直驻留。原生 range 控件在深色面板里毫无对比度，而且拖动滑杆时每个 tick 都发布一次 Host settings 写入，每个往返都重新进入控制器的 adopt 路径：滑块肉眼可见地落后于光标。

## 决策

计量器留在 composer 发送按钮旁；常驻的只有圆环，其 tooltip（提示）承载本地化整句加 `~已用 / 容量` 数字。

用悬停交换取代常驻读出：悬停圆环时，统计行的计费组（缓存命中、输入／输出 token）被替换为启发式组成明细行——系统提示词、工具、对话消息，带计量器的色板色调——经由一个共享模块存储（`contextMeterHover`），因为圆环（composer bar）与统计条（composer dock）是没有共同属主的兄弟槽位。移开即换回计费组；没有 breakdown 投影的会话即使悬停也保留计费组——交换无物可渲染，而不是渲染空条。

限制 `<select>` 及其预设列表改为一条从 8K 到路由窗口、步进 8K 的滑杆，右端即不限制状态——与窗口相等的上限永远不会生效，因此拖到那里写入的是清除——所选上限旁的 `✕` 提供显式清除；落在步进之间的 `settings.yaml` 上限原样展示。滑杆使用自定义外观（发丝轨道、业务蓝滑块外加表面色描边）以在深色面板上形成对比。单击圆环在 composer 上方打开面板，让百分比变得直观：本地化读数包夹着百分比，`~已用 / 容量` 数字点名分母，比例条与组成明细行（系统提示词、工具、对话消息）展示已占份额的构成。

Host 写入经 `CompactionPolicyController` 内 300ms 尾随防抖合并：本地回显保持同步——滑杆永远不等网络——每个字段的最终值只发布一次。

## 曾考虑的替代方案

**头部内嵌计量器加常驻数字读出。** 否决：控件条挤占标题行，而点击外部就藏掉数字的体验像 bug；统计行本来就拥有「composer 下方的数字」这个位置，悬停交换是复用它而不是再加一个。

**保留选择器并再加滑杆。** 否决：一个值配两个控件正是选择器造成的困惑；滑杆覆盖每个预设以及其间的一切取值。

**每个 tick 都直写、不做防抖。** 否决：网络就是卡顿本身。

## 后果

头部实用工具槽位回到空置，composer 末行照旧承载圆环。统计行的计费组仍是静息状态，没有丢失任何持久数字——组成是估算值，只在悬停期间借用统计条。`packages/client/ui-conversation/tests/context-meter.client.spec.tsx` 覆盖圆环、面板生命周期（切换、超时关闭、外部点击、Escape、压缩保持）、限制滑杆与悬停存储翻转；`chat-stats.client.spec.tsx` 覆盖双向交换与无 breakdown 回退；`compaction-policy.client.spec.ts` 覆盖同步回显、单次合并写入与防抖冲刷。
